Локальный AI‑работник для 1С:Предприятие 8.3

Данные 1С не покидают ваш контур. Никогда.

«Периметр» отвечает на вопросы по вашей базе 1С, делает сверки и готовит черновики документов. Модель на 744 млрд параметров работает с локального диска — в вашей серверной, без единого запроса в интернет.

Почему не облачные модели

ПАНЕЛЬ 1 · НАЗНАЧЕНИЕ

Данные 1С — это всё

Контрагенты, обороты, зарплаты, персональные данные. Отправка их во внешний API — риск по 152‑ФЗ и утечка коммерческой тайны в один запрос.

ИБ скажет «нет» — и будет права

«Периметр» спроектирован от обратного: локально — не режим работы, а единственный режим. Внешних вызовов нет ни в коде, ни в зависимостях.

Частная модель — уже реальность

Открытые веса GLM‑5.2 (MIT) и движок colibri держат модель уровня фронтира на вашем железе — от 16 ГБ RAM и одного NVMe, GPU не обязателен.

Раскатка в контуре заказчика

ПАНЕЛЬ 3 · ПОРЯДОК ВВОДА В ЭКСПЛУАТАЦИЮ
ШАГ 01 1–2 недели

Обследование и пилот

Выделяется сервер внутри контура (от 16 ГБ RAM, ~380 ГБ NVMe). Администратор 1С публикует тестовую базу со стандартным интерфейсом OData — штатная операция платформы 8.3, доработки конфигурации не требуются. Прогоняем три эталонных сценария на ваших данных.

ШАГ 02 1 день

Офлайн‑установка

Дистрибутив автономен: зависимости вендорены, pip и интернет не нужны. Веса модели конвертируются из официального источника один раз — единственный сетевой шаг, выполняется на отдельной машине и переносится носителем, если контур закрыт полностью.

  • сборка движка: make -C vendor/colibri/c portable — gcc, без загрузок;
  • config/perimeter.yaml — разрешённые хосты: только ваши серверы 1С;
  • пароль пользователя ИБ — keyring или переменная окружения, в конфиге его нет.
ШАГ 03 1–3 дня

Подключение баз

Типовые «Бухгалтерия 3.0», «Управление торговлей 11», «ЗУП 3.1». Имена объектов метаданных не зашиты в код — они в настраиваемых файлах соответствия; при первом подключении «Периметр» сверяет их с $metadata вашей базы и показывает расхождения до начала работы.

ШАГ 04 ваш регламент

Приёмка службой ИБ

Мы не просим верить на слово — воздушный зазор проверяется:

  • статический скан всего кода на внешние URL и IP — в комплекте;
  • демо‑прогон всех сценариев в сетевом пространстве без интернета (netns);
  • рантайм‑страж блокирует соединения вне списка хостов и пишет попытку в журнал;
  • append‑only журнал каждого действия — готовый артефакт для вашего SIEM.
ШАГ 05 постоянно

Эксплуатация

Пользователи работают через локальный веб‑интерфейс. Создание документов — только черновики и только после явного подтверждения человеком; проведение остаётся в 1С. Обновления — офлайн‑пакетами по вашему графику: автообновлений нет по определению.

ИЗДЕЛИЕ АВТОНОМНО · ТЕЛЕМЕТРИЯ ОТСУТСТВУЕТ

Формуляр безопасности

ПАНЕЛЬ 4 · ПОКАЗАТЕЛИ ЗАЩИТЫ
ТребованиеИсполнение
Исходящие соединения Запрещены, кроме localhost и серверов 1С из конфигурации. Контроль тройной: статический скан в CI, тестовый прогон без сети, рантайм‑страж на уровне сокетов.
Изменение данных в 1С Агент создаёт только черновики и только после подтверждения человека. Метода «провести документ» в коде не существует.
Журналирование append‑only JSONL: запрос → вызовы инструментов → подтверждения/отказы → ответ. Дозапись на уровне ОС, API перезаписи нет.
Секреты Пароли 1С — системный keyring или переменные окружения. В файлах конфигурации — только плейсхолдеры.
Зависимости Runtime‑зависимостей pip — ноль. Вендорены и проаудированы: движок colibri (Apache‑2.0), PyYAML (MIT). Реестр — docs/deps.md.

Код открыт и бесплатен

ПАНЕЛЬ 6 · КОМПЛЕКТ ПОСТАВКИ

Весь код «Периметра» — под лицензией MIT: используйте, изучайте, дорабатывайте, в том числе коммерчески. Ваша служба ИБ может прочитать каждую строку, которая окажется в контуре, — мы считаем это обязательным свойством продукта такого класса.

python3 perimeter/run_perimeter.py
