Локальный AI‑работник для 1С:Предприятие 8.3

Данные 1С не покидают ваш контур. Никогда.

«Периметр» отвечает на вопросы по вашей базе 1С, делает сверки и готовит черновики документов. Модель на 744 млрд параметров работает с локального диска — в вашей серверной, без единого запроса в интернет.

РАЗДЕЛ 1 · НАЗНАЧЕНИЕ

Почему не облачные модели

1.1

Данные 1С — это всё

Контрагенты, обороты, зарплаты, персональные данные. Отправка их во внешний API — риск по 152‑ФЗ и утечка коммерческой тайны в один запрос.

1.2

ИБ скажет «нет»

И будет права. «Периметр» проектировался от обратного: served‑локально — не режим, а единственный режим. Внешних вызовов нет ни в коде, ни в зависимостях.

1.3

Частная модель — уже реальность

Открытые веса GLM‑5.2 (лицензия MIT) и движок colibri позволяют держать модель уровня фронтира на своём железе — от 16 ГБ RAM и одного NVMe.

РАЗДЕЛ 3 · ПОРЯДОК ВВОДА В ЭКСПЛУАТАЦИЮ

Раскатка в контуре заказчика

3.1

Обследование и пилот 1–2 недели

Выделяется сервер внутри контура (от 16 ГБ RAM, ~380 ГБ NVMe; GPU не обязателен). Администратор 1С публикует тестовую базу на веб‑сервере со стандартным интерфейсом OData — это штатная операция платформы 8.3, доработки конфигурации не требуются. Прогоняем три эталонных сценария на ваших данных.

3.2

Офлайн‑установка 1 день

Дистрибутив полностью автономен: все зависимости вендорены в репозиторий, pip и интернет при установке не нужны. Веса модели конвертируются из официального источника один раз (единственный шаг, требующий сети — выполняется на отдельной машине и переносится носителем, если контур закрыт полностью).

  • сборка движка: make -C vendor/colibri/c portable — один C‑файл, gcc, без загрузок;
  • в config/perimeter.yaml перечисляются разрешённые хосты — только ваши серверы 1С;
  • пароль пользователя ИБ — в системном keyring или переменной окружения, в конфиге его нет.
3.3

Подключение баз 1–3 дня

Поддерживаются типовые «Бухгалтерия 3.0», «Управление торговлей 11», «ЗУП 3.1». Имена объектов метаданных не зашиты в код — они лежат в настраиваемых файлах соответствия, и при первом подключении «Периметр» сам сверяет их с $metadata вашей базы и показывает расхождения до начала работы.

3.4

Приёмка службой ИБ по вашему регламенту

Мы не просим верить на слово — воздушный зазор проверяется:

  • статический скан всего кода на внешние URL и IP — входит в комплект;
  • демонстрационный прогон всех сценариев в сетевом пространстве без интернета (netns) — всё работает;
  • рантайм‑страж блокирует любое соединение вне списка разрешённых хостов и пишет попытку в журнал;
  • append‑only журнал каждого действия агента — готовый артефакт для вашего SIEM.
3.5

Эксплуатация постоянно

Пользователи работают через локальный веб‑интерфейс. Создание документов — только черновики и только после явного подтверждения человеком; проведение остаётся в 1С. Обновления — офлайн‑пакетами по вашему графику, автообновлений нет по определению.

РАЗДЕЛ 4 · ПОКАЗАТЕЛИ ЗАЩИТЫ

Формуляр безопасности

ТребованиеИсполнение
Исходящие соединения Запрещены, кроме localhost и серверов 1С из конфигурации. Контроль тройной: статический скан в CI, тестовый прогон без сети, рантайм‑страж на уровне сокетов.
Изменение данных в 1С Агент создаёт только черновики и только после подтверждения человека. Метода «провести документ» в коде не существует.
Журналирование append‑only JSONL: запрос → вызовы инструментов → подтверждения/отказы → ответ. Файл дозаписывается на уровне ОС, API перезаписи нет.
Секреты Пароли 1С — системный keyring или переменные окружения. В файлах конфигурации — только плейсхолдеры.
Зависимости Runtime‑зависимостей pip — ноль. Вендорены и проаудированы: движок colibri (Apache‑2.0), PyYAML (MIT). Реестр — docs/deps.md.

РАЗДЕЛ 6 · КОМПЛЕКТ ПОСТАВКИ

Код открыт и бесплатен

Весь код «Периметра» — под лицензией MIT: используйте, изучайте, дорабатывайте, в том числе коммерчески. Ваша служба ИБ может прочитать каждую строку, которая окажется в контуре, — мы считаем это обязательным свойством продукта такого класса.
