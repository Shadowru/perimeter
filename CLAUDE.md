# Проект «Периметр»

Ты — инженерный агент проекта «Периметр»: локальный AI-работник для компаний СНГ.

**Формула продукта:** агентское ядро в духе openworker + интеграция с 1С + весь инференс локально через colibri (JustVugg/colibri, GLM-5.2 MoE с диска). Никаких внешних API.

## Железное правило №0 — воздушный зазор

В production-коде **ЗАПРЕЩЕНЫ** любые исходящие сетевые вызовы за пределы localhost и адресов из `config/perimeter.yaml` (там могут быть только внутренние хосты 1С).

- Никаких телеметрий, auto-update, CDN, шрифтов с гугла, pip/npm-зависимостей, которые звонят домой в рантайме.
- Все зависимости вендорятся в репозиторий.
- CI-проверка: статический скан кода на `http://`, `https://`, сокеты к внешним IP; тест, запускающий продукт в netns без интернета, — все сценарии должны проходить.

## Этап 1. Ресерч и юридика (первым, отчет в docs/research.md)

- Склонировать и изучить `andrewyng/openworker` и `JustVugg/colibri`: архитектура, точки расширения, формат промптов/инструментов, лицензии.
- Зафиксировать лицензии всех компонентов и веса модели GLM-5.2 (лицензия модели отдельно от лицензии движка!). Если что-то запрещает коммерческое использование или требует копилефт — остановиться и описать варианты замены.
- Изучить способы интеграции с 1С:Предприятие 8.3 и выписать, что реализуемо без доработок конфигурации: стандартный OData-интерфейс, HTTP-сервисы, COM-соединение (Windows), выгрузки. Целевые конфигурации: Бухгалтерия 3.0, УТ 11, ЗУП 3.1.

## Этап 2. Скелет репозитория

```
perimeter/
  core/          # ядро агента (форк/адаптация openworker)
  inference/     # обертка над colibri: OpenAI-совместимый локальный сервер
  bridge-1c/     # коннектор к 1С (OData/HTTP-сервисы), Python
  skills/        # навыки: "проведи сверку", "найди документ", "отчет по контрагенту"
  ui/            # минимальный локальный веб-UI (без внешних ассетов)
  config/        # perimeter.yaml — единственное место с разрешенными хостами
  vendor/        # все вендореные зависимости
  tests/
  docs/
```

- Язык: Python 3.12 для core/bridge, C — только внутри vendored colibri.
- Все русскоязычные строки — в ресурсных файлах, i18n с первого дня (ru базовый, en вторичный).

## Этап 3. inference/ — локальный мозг

- Завендорить colibri, собрать, написать smoke-тест генерации.
- Поднять поверх него HTTP-сервер на localhost с OpenAI-совместимым `/v1/chat/completions` (стриминг обязателен) — чтобы core мог работать с любым локальным бэкендом (colibri сейчас, llama.cpp как fallback).
- Замерить и задокументировать: токены/сек, потребление RAM/диска, минимальные требования к железу. Это пойдет в маркетинг, цифры должны быть честные.

## Этап 4. bridge-1c/

- Реализовать клиент OData 1С: аутентификация, чтение справочников (Контрагенты, Номенклатура), документов (Реализация, Поступление), постраничная выборка, ретраи.
- Собрать мок-сервер 1С OData для тестов (записанные реальные ответы структуры стандартной Бухгалтерии 3.0) — тесты не должны требовать живой 1С.
- Определить слой инструментов для агента: `find_document`, `get_counterparty`, `ledger_report`, `create_draft_document` (создание — только черновики, проведение документов агентом запрещено без явного подтверждения человека).

## Этап 5. core/ — агент

- Адаптировать цикл openworker под локальную модель: учитывать меньший контекст и скорость — агрессивная суммаризация истории, инструменты с компактным выводом.
- Системный промпт на русском, тон делового ассистента. Все ответы со ссылками на конкретные документы 1С (номер, дата).
- Guardrails: агент никогда не изменяет данные в 1С без подтверждения; журнал всех действий в append-only лог (аудит для ИБ — это фича продукта).

## Этап 6. Демо-сценарии (приемочные тесты)

1. «Найди все непроведенные реализации за июль по контрагенту X».
2. «Сверка: что мы отгрузили ООО "Ромашка", но не получили оплату».
3. «Подготовь черновик счета на основании прошлого заказа».

Каждый сценарий — e2e-тест против мок-1С с локальной моделью (можно маленькой, для CI), плюс ручной прогон на полной GLM-5.2.

## Правила работы

- Коммиты мелкие, Conventional Commits, сообщения на английском.
- После каждого этапа — обновлять `docs/STATUS.md`: что сделано, что заблокировано, замеры.
- Ничего не выдумывать про 1С: если нет уверенности в имени поля OData — пометить TODO и сделать конфигурируемым, не хардкодить догадку.
- Секреты (пароли 1С) — только через локальный keyring/env, в конфиге плейсхолдеры.
- Перед добавлением любой зависимости: проверить лицензию, размер, наличие сетевых вызовов; вписать в `docs/deps.md`.
